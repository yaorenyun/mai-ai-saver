# 详细工作流与边界情况

> 本文档是 `SKILL.md` 工作流的展开说明，供开发者与评审参考。

## 一、五步工作流详解

### 1️⃣ 意图解析

从用户自然语言中提取结构化参数：

| 参数 | 示例 | 默认值 |
|------|------|--------|
| 预算 `budget` | 「30 块」「不超过 50」 | 无（缺失时反问） |
| 必点 `must` | 「想吃巨无霸」「来个板烧」 | 空 |
| 排除 `exclude_tags` | 「不吃辣」「要低卡」 | 空 |
| 人数 | 「两个人吃」 | 1（暂按单人份推荐，多人提示拼单） |

**模糊处理**：预算未给时，先问「预算大概多少」；
口味模糊（「随便」）时不加约束直接算。

### 2️⃣ 数据获取

调用 `mcp_client.py` 的 `query(tool)`：

```
get_menu → get_coupons → get_nearby_stores → get_activities
```

降级链路：MCP 连接失败 → stderr 提示 → 读 `references/menu-data.json`。
**Skill 回复中必须标注数据来源**（实时 MCP 数据 / 演示数据）。

### 3️⃣ 组合优化（price_optimizer.py）

1. **必点解析**：单品 id → 收集所有包含它的套餐 → 组内按「节省金额降序」选
   第一个装得下预算的（套餐优先）；都装不下则保留单品并提示超支
2. **约束过滤**：必选项剔除排除标签；可选池过滤超预算单品
3. **有界枚举**：必选之外最多补 3 件；候选按性价比预筛前 12 个
4. **双维打分**：
   - 满足度 `satisfaction`：启发式（主食 6-10 / 小食 3-5 / 饮料 2-5 / 甜品 4）
   - 完整度 `completeness`：主食 +6（1+1 轻食档 +3）、饮料 +3、小食 +2
   - 综合分 = 满足度 + 完整度；同分比价格低者胜出
5. **输出 TOP 3**

> 规模说明：当前候选约 21 项，有界枚举可解释、可复现；
> 若菜单规模显著增大，可将枚举替换为背包 DP（`max(满足度)` 约束下
> `总价 ≤ 预算`），接口保持不变。

### 4️⃣ 券后验算（coupon_matcher.py）

对 TOP 1（或用户指定）方案试算全部可用券：

- **满减券**：订单额 ≥ threshold 时实省 = discount
- **折扣券**：实省 = min(订单额 × (1-rate), max_discount)
- **单品券**：订单包含指定商品时实省 = discount
- 按实省降序，推荐最优 + 备选

**不叠加原则**：默认只推一张；用户追问"能不能叠"时，
说明以 MCP 订单试算为准，不臆造规则。

### 5️⃣ 输出建议

固定结构（见 SKILL.md「输出规范」）：

1. 结论先行（推荐方案 + 券后价）
2. 方案对比表（明细 / 总价 / 得分 / 徽章）
3. 省钱依据（升档省了多少、券省了多少）
4. 门店推荐（最近门店 + 是否 24h + 得来速）
5. 免责声明（以 App 实时为准）

## 二、边界情况处理

| 场景 | 处理 |
|------|------|
| 预算为 0 或负数 | 拒绝计算，提示有效预算 |
| 必点项不存在 | stderr 提示「未找到」，按无必点继续 |
| 必点命中排除标签 | 剔除该必选项并提示 |
| 必选超预算 | 保留方案 + ⚠️ 超支标注，不硬凑 |
| 全部候选被排除 | 返回「没有可行方案」，建议放宽条件 |
| MCP 与离线数据冲突 | 以 MCP 为准；若 MCP 异常已降级，必须注明演示数据 |
| 优惠券规则变化 | 不在本地臆造，引导以 App/MCP 试算为准 |
| 多人用餐 | 按单人份推荐并提示「多人建议分单凑满减」 |

## 三、已知取舍（如实说明）

1. **演示数据是拍脑袋的**：`menu-data.json` 的价格/满足度为构造数据，
   真实效果取决于麦当劳 MCP 返回；接入官方 MCP 后需重新校准
2. **满足度是启发式**：无真实用户行为数据支撑，权重为经验值
3. **1+1 随心配简化建模**：mock 中按「小薯条+小可乐」计，
   实际为红区/白区各选一件，接入后应支持双区选择
4. **不处理复杂叠加**：如「单品券 + 满减」叠加，以官方试算为准
